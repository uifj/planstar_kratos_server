# 企划星产品定位

> 适用版本：planstar 单体 · 最后核对：2026-11-07 · 维护：产品组
> 本文是产品定位、品牌表达与品类边界的**唯一事实源**。文案、分类、数据模型与种子数据出现冲突时，以本文为准。

## 1. 一句话定位

**企划星是一个「企划支持平台」：创作者发布企划与回报，用户用资金支持企划落地，并获得周边、内容或参与权益。**

- 最小交易单元：**企划**
- 行为动词：**支持**
- 闭环终点：**企划达成并交付**
- 周边是企划的回报载体，不是交易标的

## 2. 核心价值主张

| 角色 | 价值主张 |
| --- | --- |
| 支持者 | 用可承受的小额资金，换取「参与创造」的成就感、限定周边/内容/权益，以及同好社群归属 |
| 创作者 | 用企划验证需求、筹集启动资金、锁定种子用户、预售周边，降低库存与冷启动风险 |
| 平台 | 以企划为内容单元，形成「发现 → 支持 → 交付 → 再创作」的内容飞轮 |

价值公式：**内容发现（种草）+ 支持共创（参与）+ 回报交付（确定性）+ 同好社区（关系）**。

## 3. 与电商 / 众筹 / 售票平台的核心差异

| 维度 | 普通电商 | 众筹平台 | 售票平台 | 企划星 |
| --- | --- | --- | --- | --- |
| 交易标的 | 现货商品 | 项目融资份额/回报 | 演出/赛事入场权 | **企划能否落地** |
| 用户动机 | 即时消费 | 投资或尝鲜 | 现场体验 | **认可价值 + 参与共创** |
| 价值兑现 | 下单即得 | 项目成功后回报 | 到场核销 | **达成后交付周边/内容/权益** |
| 不确定性 | 低 | 高，强调风险 | 低 | **中，透明披露 + 未达成退款** |
| 关系周期 | 一次性 | 项目周期 | 一次性 | **企划全周期 + 长期关注创作者** |
| 内容组织 | SKU/类目 | 项目列表 | 演出日历/城市 | **企划故事 + 进度 + 支持者** |
| 核心指标 | GMV/转化率 | 融资额/成功率 | 出票量 | **企划达成率/支持人次/复支持率** |

三句话区分：

- **不是电商**：用户买的不是现货，而是「让企划发生」的参与权，周边是回报而非商品。
- **不是众筹**：不做股权、分红、利息等金融化表达，不做重资产项目融资，强调同好支持与内容共创。
- **不是售票**：演出/见面会/试玩只是企划的一种线下回报形式，票务能力降级为可选履约能力。

## 4. 关键语义：支持 ≠ 购买 / 投资 / 捐赠

| 行为 | 是否有偿 | 是否追求财务回报 | 是否共担不确定性 | 是否参与共创 |
| --- | --- | --- | --- | --- |
| 购买 | 是（等价交换） | 否 | 否 | 否 |
| 投资 | 是 | 是 | 是 | 弱 |
| 捐赠 | 否 | 否 | 是 | 弱 |
| **支持** | **是（回报）** | **否** | **是（透明披露）** | **是** |

禁止在对外文案中使用「保本、收益、分红、稳赚、理财」等金融化表达；「未达成」应表述为「自动退款」，而非「商品失败」。

## 5. 品牌表达与 3 秒理解

**主 slogan：让喜欢的企划，真的发生。**

备选 slogan：

- 「为好企划，投一颗星。」
- 「你支持，它成型。」

**3 秒定位描述：** 发现游戏、小说、同人、面经等企划，用一份支持，换一份周边与参与。

**品牌释义：** 每一份支持是一颗星，星越多，企划越亮；企划星不是商店，是企划发生的地方。

**可理解性验收：**

- 3 秒：看到 slogan + 企划卡（封面、目标金额、达成率、支持人数），能说出「这是支持企划的平台」。
- 10 秒：看到回报档位，能说出「支持后能得到周边/内容/权益」。
- 30 秒：看到进度更新与风险说明，能说出「不是买现货，而是等企划做出来」。

## 6. 目标用户分层

| 层级 | 人群画像 | 核心需求 | 产品抓手 |
| --- | --- | --- | --- |
| L1 企划创作者 | 独立游戏/桌游制作人、同人社团、画师/写手、网文作者、面经/求职内容创作者、校园社团、独立乐队/播客 | 验证需求、筹启动资金、预售周边、种子用户、作品曝光 | 企划发布工具、回报档位设计、进度更新、创作者主页与认证、履约支持 |
| L2 深度同好 | 18–30 岁，ACG/同人/独立游戏/网文/求职社区活跃用户 | 参与感、身份认同、限定周边、抢先体验、社群归属 | 企划故事、支持者墙、限定档位、进度订阅、社群话题 |
| L3 泛内容用户 | 被内容种草的路人，价格敏感、决策快 | 低门槛、回报清晰、风险可感知 | 9.9–99 元轻档位、电子内容回报、达成率背书 |
| L4 周边收藏玩家 | 谷子/手办/限定周边收藏者 | 限定、编号、独家、晒单与流通 | 限定档、编号权益、开箱晒单、收藏墙 |
| L5 B 端机构 | 工作室、出版社、发行、品牌、校园组织 | 联名企划、IP 孵化、精准触达圈层 | 机构认证、联名模板、数据看板 |

运营重点：**L2 决定达成率，L3 决定规模，L1 决定供给质量，L5 决定商业化上限。**

## 7. 核心业务闭环

```
发现企划 → 认可价值 → 出资支持 → 企划推进（共创） → 达成/未达成 → 回报交付 → 晒单传播 → 复支持/新企划
```

| 环节 | 关键动作 | 产品能力 | 成功判据 |
| --- | --- | --- | --- |
| 发现 | 逛首页、分类、话题、榜单、搜索 | 企划卡（故事封面 + 达成率 + 支持人数 + 剩余天数） | 点击率、详情到达率 |
| 认可 | 看故事、回报、进度、创作者信用、风险说明 | 企划详情、创作者主页、FAQ、进度更新 | 停留、收藏/关注率 |
| 支持 | 选回报档位、填地址/权益信息、支付 | 支持档位、支持单、早鸟/限量、匿名支持 | 支持转化率、客单价 |
| 共创 | 关注进度、留言、参与解锁目标 | 进度更新、支持者留言、解锁目标、社群话题 | 互动率、进度打开率 |
| 达成 | 到期结算，达成进入交付，未达成自动退款 | 达成状态机、退款规则、风险披露 | 达成率、退款时效 |
| 交付 | 周边发货、电子内容发放、线下权益核销 | 履约单、物流、内容发放、核销码 | 履约率、交付满意度 |
| 传播 | 晒单、评价、分享、二次创作 | 开箱晒单、评价、分享海报 | 晒单率、复支持率 |

北极星指标：**企划达成率**；一级指标：支持人次、支持金额、复支持率、履约准时率。

## 8. 差异化竞争优势

1. **品类差异化**：不止 ACG 周边，覆盖「经验类企划」（面经、求职、考公考研、留学、行业报告）。
2. **心智差异化**：讲支持/共创，不讲购买/投资/众筹，降低决策压力并规避金融化合规风险。
3. **关系差异化**：以创作者为中心沉淀长期关注关系，进度更新与社群让支持者持续在场。
4. **供给侧差异化**：低门槛发布 + 回报档位模板 + 履约工具，让小体量创作者跑通「验证—筹资—交付」。
5. **内容差异化**：企划即内容、社区即货架，以故事/进度/晒单组织发现流，而非以 SKU 组织货架。

## 9. 产品边界

### 9.1 适合入驻（白名单）

| 品类 | 典型企划 | 典型回报 |
| --- | --- | --- |
| 游戏企划 | 独立游戏、桌游、跑团模组、游戏设定集 | 数字版/实体版、测试资格、设定集、制作名单 |
| 小说企划 | 原创小说、同人本、设定集、有声书、连载订阅 | 电子书/实体书、番外、签名版、连载权限 |
| 同人企划 | 同人志、画集、谷子、手办、徽章、立牌、同人音乐 | 周边、限定编号、定制权益、创作者互动 |
| 面经/经验企划 | 求职面经合集、考公考研资料、留学申请经验、行业报告、课程/训练营 | 电子资料、社群、直播/答疑、1v1 咨询 |
| 扩展品类 | 动画短片、播客、音乐专辑、小型舞台剧/见面会/试玩会、校园社团企划 | 点映/试玩、门票、感谢名单、联名周边 |

### 9.2 准入条件（同时满足）

1. 创作者可实名认证，或有可验证的作品/信用记录。
2. 企划目标、周期（建议 7–90 天）、资金用途、交付计划明确。
3. 至少一个可量化交付的回报档位。
4. 内容合规、不侵权、不虚假宣传。
5. 主动披露风险与「未达成退款」规则。

### 9.3 不适合入驻（黑名单，硬性拦截）

- 股权、分红、利息、理财、虚拟货币等**金融投资/集资**类。
- 慈善募捐、个人求助、医疗救助等**需慈善资质**的类目。
- 现货电商、代购、黄牛票务、演出票转售等**无企划落地属性**的交易。
- 盗版、侵权 IP、涉黄涉暴、赌博、传销、虚假宣传等**违法违规**内容。
- 食品药品、医疗器械、活体动物等**需特殊资质**的品类。
- 预付卡、储值、预付式消费等**资金池**类。
- 无交付承诺、无明确目标、无风险披露的**「空气企划」**。
- 纯刷单、刷量、炒作、集资诈骗等**风控红线**行为。

## 11. 落地约束

- 首页与详情页文案不得以「购票/票档/演出」作为主叙事词。
- 企划详情必须固定展示五必选区块：目标进度、回报档位、进度更新、风险说明、创作者信息。
- 在五必选区块之上，P2 增强区块（评价晒单、常见问题 FAQ、退款规则）与风险说明同屏可达，不得折叠到二级页面。
- 种子数据必须覆盖游戏/小说/同人/面经四大品类，以及进行中/已达成/未达成三种状态。
- 数据模型见 `docs/sql/15_project_domain.sql`，种子数据见 `docs/sql/14_mock_seed.sql`。

## 12. 与既有票务模型的兼容映射

定位切换不推翻已有库表：票务表原地保留，新域并行建设，读写逐步切换。

| 旧表（票务域） | 新表（企划域） | 字段映射 | 语义变化 |
| --- | --- | --- | --- |
| `planstar_catalog.activity` | `planstar_catalog.project` | `activity_id` → `project_id`；`name` → `title`；`end_time` → `deadline`；`venue` → 线下回报场地 | 演出 → 可支持企划 |
| `planstar_catalog.activity_event` | `planstar_catalog.project_update`（+ 线下回报场次） | `description` → `project_update.content`；`start_time` → `project_update.publish_time` | 场次 → 进度更新 / 线下回报场次 |
| `planstar_ticket.ticket_category` | `planstar_catalog.reward_tier` | `ticket_category_id` → `reward_tier_id`；`specification` → `title`；`low_price` → `price`；`tickets_num` → `limit_num` | 票档 → 回报档位 |
| `planstar_ticket.ticket_group` | `planstar_catalog.support_team` + `support_team_member` | `ticket_group_id` → `team_id`（仅拼团场景）；`saler_name` → 发起人 | 拼团 → 组队支持 / 助力 |
| `planstar_order.order_info` | `planstar_order.pledge` | `order_id` → `pledge_id`；`total_amount` → `support_amount`；`user_id` → `user_id` | 订单 → 支持记录 |
| `planstar_order.order_delivery` | `planstar_order.pledge` 履约字段 | `type`/`address`/`contact` → `delivery_type`/`address_id`/`contact_*`；物流单号 → `tracking_no`；电子内容 → `content_url`；权益 → `redeem_code` + `redeemed_time` | 单一发货 → 发货 / 电子内容 / 权益核销三态 |
| `planstar_payment.payment` / `planstar_payment.refund` | 复用，不改结构 | `order_id` 语义由 `order_info.order_id` 扩展为 `pledge.pledge_id` | 支付、退款链路不变 |

### 12.1 兼容原则

1. **只增不改**：`15_project_domain.sql` 不删除、不改写任何票务表，避免破坏历史数据与线下活动能力。
2. **新端只写新域**：新增流量只落 `project` / `reward_tier` / `pledge`；票务表转为只读历史。
3. **支付链路复用**：`payment` / `refund` 结构不变，仅将 `order_id` 的业务含义指向支持单，保证对账与退款逻辑零改造。
4. **履约三态化**：`physical` 用物流单号，`digital` 用内容发放地址，`right` / `offline` 用核销码与核销时间；互斥字段为空，避免「数字内容带物流单号」这类脏数据。
5. **演进路径**：票务表只读 → 历史数据迁移 → 下线；迁移与下线不在本期范围。
