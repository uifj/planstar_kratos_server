# ADR-0008: 生产审计剩余问题的技术债登记与暂缓决策

- **状态**: ACCEPTED（决策：登记为技术债，本阶段不修复）
- **分类**: DEBT（关联 SEC / ARC / OPS）
- **优先级**: 见下表（阻断项 P0，高/中风险 P1/P2）
- **影响维度**: 生产功能 / 资金安全 / 安全合规 / 发布交付
- **日期**: 2026-11-19
- **来源**: `docs/PRODUCTION_AUDIT.md`（商用生产级审计，2026-11-19）
- **修复 commit**: —（本 ADR 只登记不修复；G0/G1 的 8 项已由 `255b82e` 修复并推送）

## 背景（Context）

1. 2026-11-19 对仓库做了三条独立审计线（安全 / 数据与业务 / 部署与运维），登记 **16 项阻断 + 26 项高/中/低风险**，完整证据见 `docs/PRODUCTION_AUDIT.md`。
2. 按用户决策先修复 G0/G1 共 8 项（3 项本轮 JWT/RBAC 引入的提权/重放漏洞、1 项生产明文 Cookie、4 项目录改名遗留的发布链路问题），已由提交 `255b82e` 闭环并推送，本地 Docker 复测通过。
3. 剩余 **8 项阻断**（D1–D6、O5、O6）与 **26 项高/中/低风险**（S5–S13、D7–D17、O7–O12）用户明确要求「先落入 ADR，暂不处理」。

## 决策（Decision）

1. **全部剩余项按技术债登记，本阶段不做代码或配置变更**。写入本 ADR 不构成「已解决」，也不降低其风险等级。
2. **按触发条件管理**：每项给出「必须修复的触发条件」，未触发时保持现状；触发后必须按 `docs/PRODUCTION_AUDIT.md` 的闸门顺序修复并补测试。
3. **上线闸门仍然有效**：`PRODUCTION_AUDIT.md` §4 的 G2–G5 未被本 ADR 取消。当前版本**仅限开发与预发环境**，不得部署到公网生产。
4. **责任区分**：D1–D6 / O5 / O6 是仓库既有缺口（非 JWT/RBAC 批次引入）；S5–S13 等为纵深防御补强，不因本 ADR 而忽视。
5. **禁止静默关闭**：后续若关闭某项，必须在本 ADR 与审计报告中同时把状态改为 `FIXED` 并附 commit hash。

| **D2** | P0 阻断 | 退款审核只改标记，无渠道退款、无钱包回退、无流水 | `data/ops.go:117-129` | 依赖 D1 的支付渠道能力 | D1 修复时同步；或首次处理真实退款申请前 |
| **D3** | P0 阻断 | 支持单状态无推进方，`pledge_status` 永远 `pending`，用户永远不是支持者 | `data/project_write.go:255-264`、`data/project.go:224-237` | 依赖支付状态机（D1） | 众筹/企划支持功能对外开放前 |
| **D4** | P0 阻断 | `MAX(id)+1` 主键并发冲突，事务内 `MAX()` 产生 gap lock | `data/project_helpers.go:349-357` 及 5 处调用点 | 当前单实例低并发；改动涉及主键策略 | 并发注册/下单压测前；或出现 1062 告警时 |
| **D5** | P0 阻断 | 重复评价无唯一键，先 COUNT 后 INSERT 可并发写多条 | `data/project_write.go:96-103` | 同上，需 DDL 变更与数据清洗 | 评价功能开放写入前；或发现重复数据时 |
| **D6** | P0 阻断 | 跨库事务依赖「同一 MySQL 实例」假设，无启动断言 | `data/order.go:241,260-264` 等 | 当前部署确为同实例多 schema | **拆库、读写分离或多实例部署前** |
| **O5** | P0 阻断 | 主账号 AK/SK 曾出现在聊天记录，轮换项仍未勾选 | `docs/PRODUCTION_DELIVERY.md:239` | 属运维凭据轮换动作，非代码可修 | **任何生产上线前，无例外** |

## 后果（Consequences）

- **正面**：所有已知风险有正式决策记录、明确触发条件与证据索引；本批次可聚焦已授权的 G0/G1，不被范围蔓延拖住。
- **负面**：当前版本**不能**通过商用生产上线评审；D1–D3 未闭环意味着资金流不完整，D4/D5 在高并发下有数据正确性问题，O5 涉及已泄露凭据。
- **中性**：这些项不是新发现——大部分在 `docs/FOLLOWUP_WORK.md` 与审计报告初稿中已登记，本 ADR 只是把它们提升到正式架构决策层。
